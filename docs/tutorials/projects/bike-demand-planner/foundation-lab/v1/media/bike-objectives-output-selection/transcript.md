# Score nonnegative forecasts and freeze the next reference

## Apply an output policy to the quiet hour

The exact additive model predicts minus seventy point six eight at the quiet Monday hour, whose target is five. Its absolute error is about seventy five point six eight. Applying maximum of zero and prediction gives zero, with error five. We retain both values as separate outputs. At the busy hour, the positive forecast near one hundred and seventy five is unchanged, so the large deficit against four hundred and twenty remains. This is an explicit prediction policy, rather than a display adjustment that secretly changes what was evaluated.

## Make the policy a declared part of prediction

The raw branch returns a copy of the predictions. The nonnegative branch applies maximum with zero to every row. No rounding is introduced, and the supplied array is not mutated. Each policy has separate aligned prediction files and scores on the same identities. Applying a different policy only to a chart would make that chart inconsistent with its saved metrics. The eventual serving function must use the frozen model and policy together, although the application interface remains later work.

## Explain why clipping cannot worsen these errors

When the prediction is below zero and the target is at least zero, raw absolute error is target minus prediction. Clipping leaves error equal to the target alone, reducing it by the magnitude of the negative prediction. Squaring preserves that ordering because both errors are nonnegative. For predictions already above zero, neither error changes. The claim concerns absolute and squared error against nonnegative targets. It is not a guarantee about every possible metric or demand quantity. Clipping fixes an output constraint without teaching the missing busy hour shape.

## Score the complete output functions

The exact one hot model has seven hundred and twenty four negative validation forecasts. Clipping reduces its absolute error to about one hundred and nine point one four. The interaction model has seven hundred and fifty one negatives and reaches one hundred point five two after clipping. This can reverse a close ranking between penalties or encodings, so the policy must be explicit in the comparison table. Both are still worse than the hour and working day baseline. Retaining all rows lets us separate the constraint correction from the remaining positive forecast errors.

## Freeze a development reference after fitting

Every scaler, pilot rate and model is fitted before validation is loaded. Validation is then deliberately used to choose a development reference. We keep all twenty eight model and policy combinations, including both existing baselines. The rule minimizes validation absolute error; exact ties prefer raw policy and then deterministic model name order. Groups wins at ninety one point five seven. Its outputs are already nonnegative, so both policies tie and raw is retained. The selection file saves the model hash, policy and protocol identity for the next comparison.

## Keep the scope of the result clear

This is a frozen reference for further development, not an externally validated winner or a completed application. The same validation window has informed several comparisons, so its selected score can be optimistic. The final test remains reserved. Seventy two source checks and independent audits reproduce the saved predictions, objectives, identities and metrics. They do not supply a learner explanation or hosted recovery proof. The next review is to distinguish loss influence, weight preference, coordinate conditioning and representational capacity. That understanding is the purpose of these implementations, even when the established baseline remains the model we carry forward.
